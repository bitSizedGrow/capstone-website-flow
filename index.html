PPMIS (local) — how the system loads, per action

Every user action, traced from the click to the files that answer it, then split into 7 parts so each teammate owns a section they can explain. Traced against ppmis-local, commit 0ce58b4. 56 actions in total: 56 ÷ 7 = 8 actions per part.

How to read each action: the chips show the flow in one line. The numbered list under it is where to look, as file:line, in the order the code runs. Open the file, jump to that line, and read until the next item. If a line has moved since, search for the function name shown next to it. Rows marked NEW are features ppmis-online doesn't have yet.
What changed since the ppmis-online version of this page:
  • Inline page scripts moved into one file per page in assets/js/ (for example workspace.js, login.js, notifications-page.js). PHP hands them values through window.PPMIS_PAGE.
  • Refund schedules now go live on the refund start date (CheckRefundStart), not when Annex D is filed. The daily job is api/scheduled_tasks.php (was cron_refund_reminders.php).
  • New: notify the proponent that a project was approved (ApprovalNotice), Account settings for your own password and email (AccountSettings), and a Terminal Report that moves a Graduated project to Completed.
  • Amendments: no more step unlocks; "Record Request" replaces "Send for Approval"; an RTEC endorsement step is added when a realignment adds items; a restructuring sets new refund dates.
  • The Claude and Gemini extractors were merged into one AIExtractor.
Out of scope, as requested: modules/report/generate.php (now only the Annex D generator) and the classes only it uses: DocTemplate, DocTemplates, DocTables, DocTableEditor, DocInputDoc, DocExport, GeneratedDocs, ReportData, RevisedAnnexD, plus doc-input.js, doc-table-editor.js and report-generate.js.

Tips for the split

  • Part 1 should present first: the others all reuse its pipeline, gates and flash/redirect pattern.
  • Parts 3, 4 and 6 share workspace.php: Part 3 covers the stage cards, Part 4 the schedule and PDC cards, Part 6 the amendments card.
  • Parts 4 and 5 meet on the PDC Due Dates page: Part 5 explains how the page loads, Part 4 what the Notify and Paid buttons do.
  • CheckRefundStart is called from Parts 3, 4 and 6. Part 4 owns explaining it.
  • Role rule everyone should know: Staff do the project work; Admin can read everything, manages users and settings, and cannot open modules/project/.
  • Uploads always go through handleUpload() (includes/upload.php:10) → Azure Blob, and are read back through file.php.
